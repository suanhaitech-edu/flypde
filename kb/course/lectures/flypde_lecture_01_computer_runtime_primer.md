## 二、本讲目标

完成本讲后，学生应初步理解以下问题：

- 计算机只能处理有限长度的二进制信息。
- 计算机中的数不是数学中的实数，浮点数计算会产生舍入误差。
- 函数、向量、矩阵和张量进入程序后，通常需要通过数组、对象或稀疏数据结构表达。
- 内存是程序运行时存放数据和指令的重要位置，内存容量和访问方式会影响科学计算程序的规模和效率。
- CPU 负责执行指令，Cache 用于缓解 CPU 与内存访问速度之间的差距。
- Python 程序通过解释器运行，NumPy 和 FEALPy 的高效计算依赖数组化、张量化和底层高效实现。
- 操作系统负责管理进程、线程、文件、环境变量和计算资源。
- 命令行、文件路径、Python 环境、Git 和运行脚本，是科学计算学习中必须逐步掌握的基本工具。
- AI 生成的程序必须结合运行原理、数学意义和数值验证进行检查。

## 三、从数学公式到计算机程序

在数学课中，我们经常写下这样的对象：

- 一个区域 $\Omega$；
- 一个函数 $u(x)$；
- 一个偏微分方程；
- 一个边界条件；
- 一个函数空间；
- 一个矩阵方程 $Ax=b$。

这些对象在数学中可以是抽象的、连续的、无限维的。

但是，计算机不能直接处理抽象对象。计算机只能处理有限长度的信息，只能在有限时间、有限内存和有限精度下完成计算。

因此，当数学对象进入计算机时，必须发生一次转化：

```text
连续区域 → 网格
连续函数 → 自由度、数组或函数对象
微分方程 → 离散方程
线性算子 → 矩阵或矩阵算子
边界条件 → 程序中的约束处理
数值解 → 向量、数组或离散函数
误差分析 → 数值实验和验证过程
```

这门课要训练的，不只是写代码，而是理解这种转化。

科学计算程序设计的核心，不是把公式机械翻译成代码，而是把数学对象组织为计算机可以存储、操作、验证和复用的程序对象。

## 四、算法：解决问题的可执行步骤

### 4.1 算法是什么

算法是完成一项计算任务的步骤。

更准确地说，算法是针对某类问题给出的一组明确、有限、可执行的操作规则。

例如，求解一个线性方程组，可以有直接法、迭代法、多重网格方法等不同算法；求解一个偏微分方程，可以先建立数学模型，再进行离散，再组装线性系统，再求解，再验证误差。

在本课程中，一个典型数值算法通常包含以下结构：

```text
输入数学问题
→ 构造计算区域和网格
→ 选择离散方法
→ 构造函数空间或差分格式
→ 组装离散系统
→ 处理边界条件
→ 求解代数系统
→ 计算误差或物理量
→ 验证结果
```

### 4.2 什么是好的算法

一个好的科学计算算法，不能只停留在“看起来合理”。

它至少应满足以下要求：

- 有可靠的数学理论支撑；
- 有清晰的时间复杂度和空间复杂度意识；
- 易于在计算机上实现；
- 可以通过具体编程实验验证其有效性；
- 能够说明其适用条件和失效边界。

对于偏微分方程数值解来说，一个算法是否好，不只看公式是否漂亮，还要看它是否能在计算机上稳定运行，是否能处理合理规模的问题，是否能给出可信的误差表现。

### 4.3 数值算法必须接受编程实验检验

在纸面上正确的算法，进入程序后仍可能出错。

可能的错误包括：

- 公式推导正确，但索引写错；
- 局部矩阵正确，但全局组装错误；
- 边界条件数学表达正确，但程序处理错误；
- 程序能运行，但误差阶不对；
- 小规模例子正确，大规模例子内存不足；
- AI 生成代码形式完整，但数学含义错误。

因此，本课程强调：

> 数值算法必须同时经过数学分析、程序实现和数值实验验证。

## 五、计算机如何表示数据

### 5.1 bit、Byte 与二进制

计算机内部使用二进制表示信息。

最基本的信息单位是位，英文为 bit。一个 bit 只能表示两种状态，通常记为 0 和 1。

八个 bit 组成一个字节，英文为 Byte。

严格区分时，KiB、MiB、GiB 和 TiB 表示 1024 进制存储单位：

```text
1 KiB = 1024 Byte
1 MiB = 1024 KiB
1 GiB = 1024 MiB
1 TiB = 1024 GiB
```

日常语境中也常写作 KB、MB、GB 和 TB；阅读技术资料时，应结合上下文判断其含义。

计算机中的指令、整数、浮点数、字符、数组、图像和文件，最终都要以二进制形式存储和处理。

### 5.2 有限表示：计算机不能存下所有实数

数学中的实数是连续的，通常包含无限多位信息。

计算机中的数只能用有限长度的二进制串表示。

这意味着：

- 计算机不能精确表示所有实数；
- 计算机会对许多数值进行近似表示；
- 多次数值运算可能积累舍入误差；
- 程序得到的结果需要结合误差分析和数值实验判断可信性。

这是科学计算中非常重要的事实。

> 计算机中的数不是数学中的实数。

理解这一点，是理解数值计算误差的起点。

### 5.3 整数、浮点数与数据类型

在程序中，数据通常有类型。

常见数据类型包括：

- 整数；
- 浮点数；
- 布尔值；
- 字符串；
- 数组；
- 对象。

在科学计算中，最常见的是浮点数和数组。

浮点数用于近似表示实数。常见浮点类型包括单精度和双精度。双精度浮点数通常使用 64 位表示一个数，是科学计算中最常见的数据类型之一。

在 NumPy 中，经常可以看到类似 `float64`、`int64` 这样的数据类型。它们告诉我们，每个数在内存中占用多少空间，以及计算机如何解释这些二进制信息。

### 5.4 一个简单实验：0.1 + 0.2 为什么不一定等于 0.3

在 Python 中可以运行：

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

这个例子说明，十进制中看起来简单的小数，在二进制浮点表示中可能不能被精确表示。

因此，在科学计算中，不应简单用“两个浮点数是否完全相等”来判断结果是否正确，而应结合误差容忍度。

例如：

```python
import numpy as np

print(np.isclose(0.1 + 0.2, 0.3))
```

数值计算不是不精确的随意计算，而是在有限表示和有限误差下进行可靠计算。

## 六、内存：数学对象进入计算机后的存放位置

### 6.1 内存是什么

内存是程序运行时暂时存放指令和数据的硬件资源。

程序运行时，代码、变量、数组、矩阵、中间结果等都需要进入内存。

如果一个计算任务需要的数据超过可用内存，程序可能会变慢、崩溃，或者根本无法运行。

因此，科学计算程序设计必须具有内存意识。

### 6.2 内存可以看成线性地址空间

可以把内存粗略想象成一条很长的格子带。每个字节都有自己的编号，这个编号可以理解为内存地址。

程序通过地址访问内存中的数据。

对于初学者，不需要立即理解所有底层细节，但需要记住：

- 数据不是抽象地“存在程序里”；
- 数据必须占用内存；
- 不同数据结构占用内存的方式不同；
- 内存访问方式会影响程序效率。

### 6.3 数组：科学计算中的核心数据结构

数组是科学计算中最核心的数据结构之一。

向量、矩阵、张量都可以通过数组表达。

在 NumPy 中，一个数组通常包含以下信息：

- 数据本身；
- 数据类型 `dtype`；
- 形状 `shape`；
- 维度 `ndim`；
- 存储布局和步长信息。

例如：

```python
import numpy as np

x = np.array([1.0, 2.0, 3.0])
A = np.array([[1.0, 2.0], [3.0, 4.0]])

print(x.shape, x.dtype)
print(A.shape, A.dtype)
```

在数学中，向量和矩阵是抽象对象；在程序中，它们必须通过具体数组对象来存储和操作。

### 6.4 数组化计算为什么重要

Python 中可以使用循环完成很多计算，但普通 Python 循环往往不适合大规模科学计算。

例如，两个向量相加，可以写成：

```python
c = []
for i in range(len(a)):
    c.append(a[i] + b[i])
```

也可以写成 NumPy 数组化形式：

```python
c = a + b
```

第二种写法通常更适合科学计算，因为 NumPy 可以在底层使用更高效的实现处理连续数组数据。

这就是数组化计算的基本思想：

> 尽量把大量同类数值运算组织为数组整体运算，而不是在 Python 层逐项循环。

FEALPy 的许多设计，也与数组化、张量化和多后端科学计算有关。

### 6.5 稠密矩阵与稀疏矩阵

在数学中，矩阵可以写成一个二维表。

但在科学计算中，许多矩阵非常大，并且大部分元素为零。例如，有限元离散后得到的刚度矩阵通常是稀疏矩阵。

如果把一个巨大稀疏矩阵当作普通二维数组存储，会浪费大量内存。

因此，科学计算中经常使用稀疏矩阵存储格式。

稀疏矩阵的核心思想是：

> 只存储非零元素及其位置信息。

在 FEALPy 程序中，组装矩阵、处理边界条件和求解线性系统时，会经常遇到稀疏矩阵。

理解稀疏矩阵，是理解 PDE 数值解程序设计的重要基础。

## 七、CPU 与 Cache：程序为什么有快有慢

### 7.1 CPU 的基本作用

CPU 是执行程序指令的核心部件。

现代 CPU 通常有多个核心，每个核心可以执行计算任务。每个核心内部包含控制器、运算器、寄存器等部件。

可以粗略理解为：

- 控制器负责组织指令执行；
- 运算器负责完成算术和逻辑运算；
- 寄存器用于临时保存正在参与计算的数据；
- 多核 CPU 可以支持多个计算任务并发或并行执行。

本课程不要求系统学习 CPU 结构，但需要知道：程序最终要由 CPU 执行。

### 7.2 Cache 为什么重要

CPU 访问寄存器和 Cache 的速度通常远高于访问主内存的速度。

Cache 是 CPU 与内存之间的重要中转区域，用来提高数据访问效率。

科学计算程序中，大量时间可能不是花在数学运算本身，而是花在数据访问和内存搬运上。

因此，程序是否高效，不只取决于算法公式，也取决于数据组织方式和内存访问方式。

### 7.3 为什么数组化计算更适合科学计算

数组化计算往往能更好地利用底层高效实现、连续内存访问和硬件优化。

这也是为什么科学计算中常用 NumPy、PyTorch、JAX、FEALPy 等数组或张量计算平台。

对于初学者，可以先记住：

> 科学计算程序应尽量把大量数值运算组织成数组、矩阵或张量层面的整体操作。

这不是单纯为了代码简洁，而是为了更好地利用计算机硬件。

### 7.4 主频不是唯一指标

CPU 主频表示 CPU 每秒时钟脉冲的数量，常用 GHz 表示。

主频越高，通常意味着单位时间内能执行更多指令，但程序速度不只由主频决定。

影响程序速度的因素还包括：

- 算法复杂度；
- 内存访问方式；
- Cache 利用情况；
- 是否使用数组化计算；
- 是否使用多线程或并行计算；
- 是否调用了高效底层库；
- 问题规模和数据结构。

对于科学计算来说，理解这些因素比单纯比较 CPU 主频更重要。

## 八、程序如何运行

### 8.1 源代码不是程序运行的全部

我们写的 Python 文件只是源代码。

当执行一个 Python 程序时，通常会经历以下过程：

```text
用户输入命令
→ 操作系统找到 Python 解释器
→ Python 解释器读取源代码
→ 加载相关模块和库
→ 创建变量和对象
→ 执行函数和语句
→ 调用底层数值计算库
→ 输出结果或写入文件
```

这说明，程序运行不只是代码本身，还依赖解释器、库、文件路径、环境变量和操作系统。

### 8.2 Python 解释器

Python 解释器是执行 Python 代码的程序。

当我们在命令行中输入：

```bash
python script.py
```

操作系统会启动 Python 解释器，由解释器读取并执行 `script.py` 文件中的代码。

如果系统找不到 Python，或者找到了错误的 Python 环境，程序就可能无法运行，或者导入不了需要的库。

因此，学习科学计算程序设计，必须逐步理解 Python 环境。

### 8.3 模块导入与运行环境

在 Python 中，经常会写：

```python
import numpy as np
from fealpy.mesh import TriangleMesh
```

这表示 Python 解释器需要在当前环境中找到对应模块。

如果模块没有安装，或者安装在另一个环境中，就会出现导入错误。

常见错误包括：

```text
ModuleNotFoundError
ImportError
```

这些错误不一定是数学错误，而可能是运行环境问题。

### 8.4 NumPy 为什么比普通 Python 循环快

NumPy 的很多操作会调用底层高效实现。

当写出：

```python
c = a + b
```

NumPy 不需要在 Python 层逐个解释每一次加法，而是可以把连续数组数据交给底层高效代码处理。

因此，NumPy 数组化计算通常比普通 Python 循环更适合大规模数值计算。

### 8.5 FEALPy 程序中的数据流

一个典型 FEALPy 数值程序，通常包含如下数据流：

```text
定义区域或模型
→ 生成网格
→ 构造函数空间
→ 建立离散格式
→ 组装矩阵和右端项
→ 处理边界条件
→ 求解线性系统
→ 得到离散解
→ 计算误差或可视化结果
```

这些步骤本质上都是数学对象到程序对象的转化。

例如：

- 区域变成网格对象；
- 函数空间变成自由度组织；
- 双线性型变成矩阵；
- 线性型变成向量；
- 边界条件变成代数系统中的约束；
- 数值解变成离散函数或数组。

理解这些数据流，是学好 FEALPy 的关键。

## 九、操作系统如何管理程序

### 9.1 操作系统的作用

操作系统是管理计算机硬件资源和程序运行的软件系统。

它负责协调 CPU、内存、磁盘、文件、进程、线程、输入输出设备和用户交互。

对于科学计算学习者来说，操作系统至少承担以下作用：

- 启动程序；
- 分配内存；
- 管理进程和线程；
- 管理文件和目录；
- 提供命令行或图形界面；
- 管理环境变量；
- 协调多个任务同时运行。

### 9.2 进程：正在运行的程序

进程可以理解为正在运行的程序实例。

当你启动一个 Python 程序时，操作系统会创建一个进程。

每个进程拥有自己的资源，包括代码、数据、虚拟地址空间、打开的文件等。

如果一个程序占用太多内存，操作系统可能会使它变慢，甚至终止它。

### 9.3 线程：进程中的执行单元

一个进程至少有一个线程。

在现代操作系统中，线程通常是 CPU 调度的重要执行单元。一个进程可以包含多个线程。

在科学计算中，有些底层数值库可能使用多线程加速计算。

例如，可以通过环境变量控制某些程序使用的线程数量：

```bash
export OMP_NUM_THREADS=4
```

这类设置会影响程序性能，也可能影响课程实验结果的可重复性。

初学阶段不要求深入掌握并行计算，但需要知道：

> 科学计算程序的运行速度和资源使用，可能受到线程数、底层库和操作系统调度影响。

### 9.4 环境变量：程序运行的隐形参数

环境变量是操作系统中用于影响程序运行环境的一类变量。

常见例子包括：

- `PATH`：告诉系统到哪些目录寻找可执行程序；
- `PYTHONPATH`：影响 Python 查找模块的路径；
- `OMP_NUM_THREADS`：影响部分并行程序使用的线程数。

查看或设置环境变量，是排查科学计算程序运行问题的重要技能。

例如，在 Linux 或 macOS 中：

```bash
echo $PATH
export OMP_NUM_THREADS=4
```

在 Windows PowerShell 中：

```powershell
$Env:PATH
$Env:OMP_NUM_THREADS=4
```

### 9.5 文件系统、目录与路径

## 十一、面向 FEALPy 的最小运行图景

### 11.1 一个 FEALPy 程序通常在做什么

一个 FEALPy 程序通常不是孤立地计算一个公式，而是在组织一条完整的数值计算链。

例如，求解一个 Poisson 方程时，程序可能会做：

```text
导入 FEALPy 和科学计算库
→ 定义计算区域
→ 生成或读取网格
→ 构造有限元空间
→ 定义双线性型和线性型
→ 组装稀疏矩阵和右端向量
→ 处理边界条件
→ 调用求解器
→ 得到数值解
→ 计算误差
→ 输出或可视化结果
```

每一步都对应一个数学对象或计算对象。

### 11.2 网格、自由度、矩阵和向量

在 FEALPy 中，网格不是一张图片，而是一个包含节点、单元、拓扑关系和几何信息的数据对象。

自由度不是抽象编号，而是离散函数在程序中的组织方式。

矩阵不是简单二维表，而可能是稀疏矩阵。

向量不是纸面符号，而是内存中的数组。

边界条件不是一句话，而是进入代数系统的程序操作。

理解这些转化，才能真正理解 FEALPy 程序。

### 11.3 报错、调试与验证

运行 FEALPy 程序时，可能遇到多种问题：

- Python 环境问题；
- 模块导入问题；
- 文件路径问题；
- 数组维度不匹配；
- 矩阵大小不一致；
- 边界条件处理错误；
- 求解器不收敛；
- 误差结果异常；
- 内存不足或运行过慢。

面对这些问题，不应只问“程序为什么报错”，而应逐步定位：

```text
是环境问题？
是路径问题？
是 Python 语法问题？
是数组维度问题？
是数学离散问题？
是边界条件问题？
是求解器问题？
是误差验证问题？
```

调试科学计算程序，需要同时理解数学、程序和运行环境。

## 十二、AI 生成代码的运行原理检查

AI 可以帮助生成代码，但 AI 不一定理解当前课程环境、FEALPy 版本、数学模型边界和验证要求。

因此，面对 AI 生成代码时，需要进行运行原理检查。

至少检查以下问题：

| 检查项 | 问题 |
|---|---|
| 环境 | 代码依赖的库是否已经安装？ |
| 版本 | 代码是否适配当前 FEALPy 版本？ |
| 导入 | `import` 的模块是否存在？ |
| 数据 | 数组形状、数据类型是否合理？ |
| 内存 | 矩阵或数组是否可能过大？ |
| 稀疏性 | 大规模矩阵是否使用稀疏结构？ |
| 边界条件 | 程序是否正确处理边界条件？ |
| 求解器 | 求解器是否适合当前系统？ |
| 结果 | 程序是否做了误差计算或其它验证？ |
| 解释 | 学生是否能解释代码中的数学和程序含义？ |

AI 生成代码能运行，不等于它正确。

AI 生成解释听起来合理，也不等于它可靠。

在本课程中，AI 输出必须经过理解、运行、验证和修订。

本节检查表用于帮助学生理解 AI 生成代码的运行风险，不替代后续实验、作业和项目中的正式验证要求。

### 13.3 实验三：比较普通循环和数组化计算

运行：

```python
import numpy as np
import time

n = 1_000_000
a = np.ones(n)
b = np.ones(n)

start = time.time()
c = []
for i in range(n):
    c.append(a[i] + b[i])

```

思考：

- 哪种方式更快？

## 十四、本讲小结

本讲建立了科学计算程序设计所需的最小计算机运行图景。

请记住三条底线：

1. **计算资源有限**  
   CPU、内存、磁盘和运行时间都是有限资源。算法和程序必须面对这些限制。

2. **数值表示有限**  
   计算机中的数是有限长度的二进制表示，浮点数计算会产生舍入误差。

3. **程序结果必须验证**  
   程序能运行，不等于结果正确。科学计算程序必须通过测试、误差分析和数值实验进行验证。

本课程后续学习有限差分、有限元、FEALPy 网格、函数空间、矩阵组装和求解器时，都将建立在本讲的运行图景之上。
