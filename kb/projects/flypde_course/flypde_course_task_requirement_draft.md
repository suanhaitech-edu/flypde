# FLYPDE | Task Requirement | FLYPDE HTML 交互式课件系统需求

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/projects/flypde_course/flypde_course_task_requirement.md`
- **启用条件**：当需要界定 FLYPDE HTML 交互式课件系统项目级 Task 的真实需求与成功条件时，本文件必须启用
- **适用范围**：FLYPDE 仓库；`kb/projects/flypde_course/` 项目级任务；《FEALPy 偏微分方程数值解程序设计》课程 HTML 课件设计、开发、测试与验证场景

本文档用于界定 FLYPDE HTML 交互式课件系统项目级 Task 所要满足的真实问题、真实需求、约束条件与成功条件。

## 一、背景与核心问题

《FEALPy 偏微分方程数值解程序设计》课程的前期讲义已经形成较清晰的课程目标、问题主线与知识结构，但主要承载形态仍偏向完整阅读版 Markdown 文档。

在真实课堂与学生课后学习场景中，仅依靠长篇 Markdown 讲义，难以充分支撑以下学习活动：

- 在课堂中以图、表、代码、动画、交互组件和空间化布局组织知识；
- 让教师直接打开课件页面进行讲授，而不是在长文档中跳转和口头补充；
- 让学生在课后通过可视化、可操作、可反复查看的页面理解课程内容；
- 将数学对象、数据对象、程序对象、运行过程和验证结果之间的关系变成可观察、可交互的学习对象；
- 通过 HTML 页面把课程内容从线性阅读材料转化为以实践、演示和理解为主线的课堂工具；
- 为后续本地 Python 运行、命令行交互、示例测试和 FEALPy 实践提供可扩展入口。

因此，FLYPDE 需要建设一套以 HTML 为主承载形态的交互式课件系统，使教师可以直接打开每讲的 `index.html` 开始讲课，使学生可以在本地仓库中直接浏览、复习、操作和理解课程内容。

该系统的核心问题不是建设云端教学平台，也不是建设 Notebook 形态的交互计算环境，而是为 FLYPDE 课程提供一种本地化、轻量化、可直接打开、表现力更强、适合课堂讲授和学生自学的 HTML 课件形态。

本 Task 所讨论的 HTML 课件系统，首先应作为课程内容的高表现力承载方式成立；本地 Python 程序运行、系统命令行访问和测试执行能力属于增强层能力，应通过 `fly` 命令启动的本地辅助服务提供，不应成为 HTML 课件本体成立的前提。

## 二、已确认需求

### 2.1 HTML 课件主形态需求

FLYPDE 课程课件应以 HTML 页面作为主要课堂展示与学生学习承载形态。

每一讲课件应能够形成可直接打开的 HTML 页面，并以 `index.html` 作为课堂入口。

教师应能够在不启动云服务器、不进入 Notebook 环境、不依赖远程平台的情况下，直接打开本地 HTML 课件进行课堂讲授。

### 2.2 直接打开需求

HTML 课件应优先支持本地直接打开。

在未启动任何本地辅助服务的情况下，课件仍应能够完成基础讲授功能，包括文字展示、图表展示、代码展示、布局组织、局部交互、动画演示和课堂问题呈现。

需要真实调用本机 Python、系统命令或测试工具的功能，可以在本地辅助服务启动后启用。

### 2.3 高表现力表达需求

HTML 课件应充分利用 HTML、CSS、JavaScript、SVG、Canvas 或其它轻量前端能力，提升课程内容的可视化表现、交互性和信息组织能力。

课件应重点改善 Markdown 长文档在以下方面的不足：

- 图示表达不足；
- 表格和结构关系展示不直观；
- 代码与解释之间缺少空间对应关系；
- 数学对象到程序对象的转化过程不够可视化；
- 课堂讲授中缺少按钮、滑块、折叠区、步骤切换、动态演示等交互手段；
- 学生课后复习时难以快速定位重点、实验和自查问题。

### 2.4 课堂讲授需求

HTML 课件应服务教师课堂讲授。

课件页面应支持围绕问题、概念图、代码片段、运行结果、实验步骤和课堂提问组织讲授流程。

课件不应只是把 Markdown 正文转换为网页，而应围绕课堂讲授重新组织内容结构，使教师可以沿着页面中的问题、图示、交互和示例推进课堂。

### 2.5 学生自学需求

HTML 课件应服务学生课后复习和自主练习。

学生应能够在 clone FLYPDE 仓库后，通过本地 HTML 页面重新查看课程内容、操作交互组件、阅读代码示例、理解实验目标，并进入后续示例运行或作业任务。

课件应降低学生从文字理解进入程序实践的摩擦，而不是只提供课堂展示效果。

### 2.6 课程内容重构需求

FLYPDE 现有 Markdown 讲义应保留为完整阅读版源资产或课程知识资产。

HTML 课件不应机械复制完整阅读版讲义，而应围绕课堂使用和学生操作进行重构。

每一讲 HTML 课件至少应表达：

- 本讲核心问题；
- 学习目标；
- 关键概念图示；
- 重要代码片段；
- 课堂互动问题；
- 可视化或交互式演示；
- 实验或练习入口；
- 学生自查问题；
- 与后续作业、示例或测试的连接。

### 2.7 轻量前端构建需求

FLYPDE HTML 交互式课件系统可以引入轻量前端构建工具，用于提升课件页面组织、交互开发、资源复用与后续维护效率。

前端技术选择应服从“静态 HTML 可直接打开”的最高约束。MVP 阶段优先采用手写 HTML / CSS / JavaScript 加轻量构建辅助的方式，不引入 React、Vue、Jupyter、Notebook 或复杂前端应用框架。

构建工具建议采用 Vite 作为开发阶段的轻量工具，但最终构建产物必须能够脱离 Vite 开发服务器直接打开。若默认模块化产物影响 `file://` 直接打开，应采用单文件 HTML、内联脚本、传统脚本打包或等价方式保证 `index.html` 的直接可用性。

构建结果应优先形成易于本地打开、易于分发、易于版本管理和易于课堂使用的 HTML 课件产物。

### 2.8 本地执行增强预留需求

FLYPDE HTML 交互式课件系统应为后续本地执行增强能力预留接口。

MVP 阶段先完成可直接打开的静态 HTML 课件原型，不把 `fly` 本地辅助服务作为首阶段必需建设内容。

后续当需要真实运行 Python 程序、执行系统命令、运行测试或调用 FEALPy 示例时，可以通过 `pipx` 安装本地命令行工具，并以 `fly` 作为统一命令行入口启动本地辅助服务。

该增强能力不应改变 HTML 课件可以直接打开和讲授的基本要求。

### 2.9 浏览器内终端预留需求

浏览器内终端属于本地执行增强层能力，不进入静态 HTML 课件 MVP 的必需范围。

后续进入本地执行增强阶段时，HTML 课件应支持浏览器内终端输入能力。终端能力应同时支持预设命令触发与学生主动输入命令。预设命令用于降低初学者进入门槛，终端输入用于训练学生真实理解命令、路径、环境、脚本运行、测试执行和错误反馈。

终端能力必须通过本地辅助服务实现，不得假定静态 HTML 页面可以直接访问系统命令行。

### 2.10 本地 Python 程序运行预留需求

本地 Python 程序运行属于本地执行增强层能力，不进入静态 HTML 课件 MVP 的必需范围。

后续进入本地执行增强阶段时，HTML 课件应支持调用学生本机 Python 环境运行课程示例程序，并展示标准输出、错误输出和必要的结果文件。

FEALPy 不作为 HTML 课件构建依赖。后续需要访问 FEALPy 时，默认假设 FEALPy 已安装在系统 Python 环境中，课件通过本地执行增强层访问系统环境中的 FEALPy。

### 2.11 可测试与可验证需求

FLYPDE HTML 交互式课件系统应支持课程示例和实验任务进入测试与验证过程。

课程实验不应只要求学生“看懂页面”或“运行成功”，还应引导学生通过测试、输出解释、误差判断或实验记录说明结果是否可信。

测试机制应优先服务教学目标，避免一开始建设复杂自动判题系统。

### 2.12 仓库结构适配需求

FLYPDE HTML 交互式课件系统的项目级设计、开发和测试过程资产应集中承载于：

`kb/projects/flypde_lab/`

HTML 课件源文件与构建产物应承载于：

`kb/course/html/`

首个 HTML 课件原型应围绕 Lecture 01 计算机运行原理入门展开。

本地执行增强层的 Python 实现应在后续阶段承载于：

`src/py/flypde_lab/`

课程讲义、HTML 课件、示例代码、测试代码、项目级设计资产和本地执行增强源码应保持清晰边界。

### 2.13 FEALPy 主平台承接需求

FLYPDE HTML 交互式课件系统应服务《FEALPy 偏微分方程数值解程序设计》课程，并以 FEALPy 为课程主平台。

FEALPy 不作为静态 HTML 课件构建依赖。后续课件需要运行 FEALPy 示例时，默认通过系统 Python 环境中已安装的 FEALPy 访问。

该系统的早期课件和实验可以从 Python、NumPy、命令行、浮点数、数组、测试等基础内容开始，但其长期方向应能支撑学生逐步进入 FEALPy 的网格、函数空间、组装、求解、误差验证和课程项目实践。

### 2.14 AI 协作学习需求

FLYPDE HTML 交互式课件系统可以为后续 AI 协作学习场景预留入口，但 AI 不应替代学生对数学模型、程序逻辑、运行结果和验证结论的理解与判断。

与 AI 相关的学习活动应服务于解释、调试、候选代码生成、错误分析、测试设计和学习记录整理，并应保留学生自我验证与责任边界。

## 三、约束条件

### 3.1 HTML 课件主位约束

本 Task 的主对象是 FLYPDE HTML 交互式课件系统，不是通用 Web App、在线教学平台、Notebook 系统或完整 IDE。

本地执行增强服务是支撑对象，不是主对象。

### 3.2 直接打开约束

HTML 课件应能够在本地直接打开并完成基础讲授与学习功能。

真实 Python 运行、系统命令执行和测试执行可以依赖本地辅助服务，但不得反向要求所有课件内容必须通过服务启动后才能查看。

### 3.3 非云端约束

FLYPDE HTML 交互式课件系统的默认使用方式必须是本地使用，不得要求教师或学生必须访问云服务器或远程平台才能完成基础讲授与学习。

### 3.4 非 Notebook 主形态约束

FLYPDE HTML 交互式课件系统不以 Jupyter Notebook 或 JupyterLab 作为主交互形态。

该约束不禁止未来在特定场景中提供 Notebook 辅助材料，但 Notebook 不应成为本 Task 所建设对象的主位形态。

### 3.5 轻量化约束

前端构建、页面组织和本地辅助服务都应服从轻量化原则。

不得在 MVP 阶段引入登录系统、云端同步、多用户管理、复杂权限系统、完整在线 IDE、复杂自动判题平台或与课程主线无关的平台化能力。

### 3.6 课程主位约束

FLYPDE HTML 交互式课件系统的建设必须服务课程讲授、学生学习、实验训练和科学计算能力培养，不应偏移为通用前端项目、通用在线 IDE 或与课程主线无关的软件系统。

### 3.7 仓库边界约束

项目级任务资产应承载于 `kb/projects/flypde_lab/`。

本地执行增强层 Python 源码应承载于 `src/py/flypde_lab/`。

课程讲义、HTML 课件、示例代码、测试代码与项目级设计资产应保持边界清晰。

不得把本项目的设计、开发、测试过程资产放入 `docs/design/` 或 `docs/ops/` 作为主承载位置。

### 3.8 学生真实能力形成约束

HTML 课件不应只追求视觉效果，也不应把学生限制在点击和观看层面。

该系统应在提升表达力和降低入门门槛的同时，逐步引导学生理解真实命令行、文件路径、Python 环境、脚本运行、错误信息、测试和验证。

## 四、成功条件

FLYPDE HTML 交互式课件系统项目级 Task 的真实需求被满足，应至少具备以下条件。

### 4.1 HTML 课件入口成立

Lecture 01 计算机运行原理入门形成可直接打开的 `index.html` 课件页面。

教师能够通过打开 `kb/course/html/lecture_01/index.html` 进入课堂讲授状态，并完成该讲的基础展示、问题引导、图表说明、代码讲解和交互演示。

### 4.2 课堂表达闭环成立

至少有一讲 HTML 课件能够围绕课程核心问题完成以下课堂表达闭环：

- 提出本讲核心问题；
- 展示关键概念或对象关系；
- 展示代码片段或程序结构；
- 通过图表、动画或交互组件辅助解释；
- 给出课堂提问或学生操作入口；
- 形成面向本讲目标的阶段性收口。

### 4.3 学生自学闭环成立

学生能够在本地仓库中打开 HTML 课件，复习课堂内容，操作页面中的交互组件，理解关键代码和图示，并根据页面提示进入后续实验或练习。

### 4.4 静态 HTML 课件原型成立

Lecture 01 HTML 课件在未启动本地辅助服务时，仍可完成基础讲授和学习功能。

静态 HTML 课件原型应能够展示核心问题、概念图示、代码片段、课堂互动、局部交互组件和学生自查问题。

### 4.5 仓库对象边界成立

项目级任务资产、Markdown 阅读版讲义、HTML 课件、源码实现、示例程序和测试代码能够在仓库中形成清晰承载边界。

不得把 HTML 课件系统的设计、开发、测试过程资产放入 `docs/design/` 或 `docs/ops/` 作为主承载位置。

### 4.6 教学价值闭环成立

FLYPDE HTML 交互式课件系统应能实质性降低课程前期学习摩擦，使教师更容易讲清楚课程主线，使学生更容易完成从阅读概念到观察图示、操作交互、理解程序、运行示例和执行测试的学习闭环。

该成功条件以课程实践效果为准，不以界面复杂度、功能数量或平台化程度为准。

## 五、待确认需求

本阶段不保留待确认需求。

已确认内容包括：HTML 课件承载目录为 `kb/course/html/`；首个 HTML 课件主题为 Lecture 01 计算机运行原理入门；MVP 阶段先完成可直接打开的静态 HTML 课件原型；前端可采用轻量构建工具辅助开发，但最终产物必须服务 `index.html` 直接打开；本阶段不建设本地辅助服务，不处理命令执行安全策略，不将 FEALPy 作为课件构建依赖。
